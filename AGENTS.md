# Project conventions

- The player-facing game title is BLOCK CRASH (블록 크래시). Existing RuneBreak code, asset paths and save keys remain stable. Entry flow: `Splash` scene → `Play` scene, with `MainPage` and `PlayPage` prefab instances registered in `PageManager`.
- Cache component dependencies in serialized prefab/scene fields. Do not use `GetComponent`, `GetComponentsInChildren`, `Find`, or `AddComponent` in runtime initialization. Editor authoring/build utilities may use these APIs to bake references.
- Inspect and reuse the existing `PoolManager`, `SpriteManager` / `SpriteAtlasSO`, and `PopupManager` regardless of their folder locations. Do not create parallel manager systems.
- Popups use the existing `PopupManager` with authored prefab references and a scene-authored `PopupParent`. Instantiating a complete popup prefab on open and destroying that instance after close is an approved exception; never build its UI hierarchy or add components at runtime. Cache its canvas, animation target, input blocker, controls and other dependencies in serialized fields.
- Settings uses the ivory molded surface from `Tools/RuneBreak/Source/BlockPunch/Surface/block-play-surface-buttons.html`. The shared `PopupPanel` / `RuneBlockUiAuthoring` path delegates to `RuneSurfaceAuthoring`. Settings is titled `Settings` and contains only `Music`, `Sound Effects` and a bottom `Close` button, identically in the lobby and gameplay. Results use a full-screen overlay with a 230/255-alpha navy curtain authored by `RuneRewardAuthoring`, with `Clear!`, a central coin pile and the reward amount. There is no title plaque or separate central star. Initially show only `Claim`; reveal amber `Home` and green `Next` after all reward coins reach the balance bar. Use the official downloaded Fredoka Medium, SemiBold and Bold TTFs and baked TMP SDF assets in `Assets/RuneBreak/Fonts/Fredoka`; retain `OFL.txt` and `SOURCE.json`. Do not draw or design a font in code.
- Author UI, boards, slots and effects in prefabs. Avoid runtime hierarchy construction; use the existing `PoolManager` baked-pool path for flights and a bounded mesh buffer for particles.
- Reuse `SpriteAtlasSO` / `SpriteManager` and point-filtered, uncompressed sprite atlases. Keep the HTML prototype's exact pixel palette and drawing geometry.
- `Tools/RuneBreak/Source/rune-break-layers.html` is the fidelity reference. The export script runs its original drawing functions. Preserve Aseprite sources and compare exported pixels before changing art.
- Rules reserve damage and storage when tapped. Animation timing must not affect rules. Keep rules/solver independent of MonoBehaviour and validate against the HTML oracle.
- Ready boosters are three empty slots; their mechanics are undecided. Lobby tabs are data-driven and currently placeholders except Home.
- The HTML is a reference for art, rules and effects, not the shipped UI. Do not restore its named chapter heading, north/east text panels, debug statistics, undo/restart/hint buttons, or Z/R/H shortcuts. PlayPage uses the board, recast slots, top-right settings, and three bottom booster placeholders.
- Legacy pixel gate presentation overrides live in `Tools/RuneBreak/presentation.cjs`. Preserve these original sources; current MainPage and PlayPage use Block Punch art.
- MainPage retains Block Punch art from `Tools/RuneBreak/Source/BlockPunch/block-punch.html`. PlayPage uses the newer ivory Surface reference above, with a 480×652 cabinet, 56-unit cells and the original vivid engraved blocks. Preserve exact PNG/Aseprite masters, two round studs on each continuous long gate, and one large remaining-hit number in its center (for example `2`, never `2/2`). Do not add a badge, `OK`, or a storage plaque. Keep future-layer previews. `RunePunchAuthoring` delegates the current PlayPage skin to `RuneSurfaceAuthoring`; `RuneLobbyPunchAuthoring` authors MainPage. Both use the existing `SpriteAtlasSO` and the point-filtered, uncompressed BlockPunch atlas. `export-surface.cjs`, `author-surface.lua`, and `comfy-surface.cjs` preserve the supplied material pixels; ComfyUI alpha roundtrip verification keeps exact Aseprite composites as the shipped masters.
- MainPage uses the navy/violet glossy skin, rounded icons and gold Play button. Its center is a large two-line BLOCK CRASH wordmark with exactly four decorative red/blue/gold/green molded blocks from the existing atlas. `RuneLobbyHeroAuthoring` bakes the Fredoka Bold title, shadows and block references into MainPage; `RuneLobbyHero` gives the title and blocks independent, slow bobbing and slight rotation. All decoration is non-interactive, pauses while settings is open and rests in reduced motion. The old six-block showcase, gate, particles and unused lobby flight pool are removed from the prefab; historical showcase code remains available. Keep existing navigation/button bindings and the existing reward pool systems. The background fills the entire canvas, while controls use the existing safe-area layout. Glossy panel recipes live in `RuneLobbySkinAuthoring`; coin/heart recipes are in `Tools/RuneBreak/export-lobby-icons.cjs`, with layered Aseprite masters in `Tools/RuneBreak/Source/BlockPunch/Lobby/Icons`. Currency icons share the existing BlockPunch atlas.
- Storage flights use the prototype's punch rebound: straight approach, local compression, inward kick, curved flight and landing. `RuneReboundMotion` is pure presentation; preserve its original `Create` path for the HTML oracle and lobby. Surface flights use `CreateSurface` with a stronger spring release, stretch, rotation and ricochet sound. If the destination has no gate, rebound at the actual cabinet frame (north 45, east 451, south 486, west 29 in Surface coordinates), then fly to the reserved storage slot. Damage and storage remain reserved by the existing rules at tap time. Author all shadows, afterimages and ribbons in the existing 48-instance baked pool.
- Surface storage launches automatically from the leftmost eligible slot after landing (0.12 seconds, or 0.065 in reduced motion), only when the matching logical and visible gate layers agree, at 0.085-second intervals. Slots have no manual click action. `RuneAutoRules` mirrors the HTML automatic solver; each automatic launch uses the existing rule transition to reserve damage once. Settings pauses this scheduler. Surface impacts use the original `DepthFX` beveled solids, rotation, lighting, detached shadows and two floor bounces through the existing `RuneFxGraphic`, bounded to 190 fragments. Verify with `verify-surface-motion.cjs` and `SurfaceMotionQA.cs`.
- Rapid taps must not lose solely because a guaranteed automatic departure is still animating. Before a valid board tap would overflow, reserve the leftmost logically eligible stored block's automatic shot immediately, then apply the board tap to the freed slot. Keep five logical slots and the existing rules; if no stored block can target a logical gate, overflow still loses. Schedule the reserved flight after its incoming landing, settle delay, prior-layer reveal and launch cadence. Schedule the replacement arrival after that pocket's departure. `storageView` keeps the departing block visible until its scheduled start; future automatic flights remain rented but hidden in the existing baked pool. Reset returns these hidden reservations too. `StoragePressureQA` reproduces level 5 with four gold blocks stored and four rapid green taps, compares the settled result with the HTML automatic rules across normal/reduced motion and frame rates, and verifies pause, real overflow and pool cleanup.
- The main Play button displays only `Lv. N`, following saved progress. Long buttons use one molded face with no extra foundation: gold Lv./Close/Claim, amber Home/Retry and green Next. The cached `RuneRaisedButton` scales the centered face and its label to 0.96 over 0.07 seconds, then returns over 0.14 seconds using unscaled time; pointer exit cancels and disable resets the pose. Reduced motion snaps between poses. Small controls retain their existing behavior. Buttons and popup frames derive their curved bevels and round studs from the original stored block art, baked to each control's dimensions to avoid distorted studs. Recipes: `Tools/RuneBreak/export-block-ui.cjs --single-buttons` and `author-single-buttons.lua`; layered Aseprite sources: `Tools/RuneBreak/Source/BlockPunch/Lobby/Blocks`. Register their point-filtered, uncompressed sprites in the existing BlockPunch atlas.

- All current player-facing copy is English, including lobby tabs, settings, result states, Splash and level/demo descriptions. Localization is planned later. `RuneEnglishAuthoring` bakes the downloaded fonts and applies the English labels; original HTML references remain unchanged.
- Results use the standalone `Resources/Prefabs/Popups/ResultPopup.prefab` with cached `RuneResultPanel` controls, registered alongside settings in the existing scene `PopupManager`. No result UI is embedded in PlayPage. The page passes result data and handles the action after the popup closes; progress awards stay in the page. Next/Home/Retry and back navigation must close and destroy the popup instance.
- Result overlays block gameplay input while existing flights, fragments, captions and shake finish naturally. Settings still pauses gameplay presentation and automatic storage launches. Delay the clear overlay until the final `Break!` caption has faded; do not freeze fragments to show a result.
- `RunePlayPage.clearRewardCoins` is inspector-configurable and defaults to 40. `RuneCoinReward` credits a claim once and saves balance plus receipt together under `RuneBreak.Wallet`; animation timing never determines payment. Both pages display this balance. ResultPopup contains 12 authored `RuneCoinFlight` objects in a prefab-local `RuneLobbyFlightPool`, reusing the existing `PoolManager` baked-pool path. Block duplicate claims and navigation during collection, return every coin to the pool, then enable Next/Home. Failed levels grant no coins.
- Popup prefab files, root objects and lookup names are `SettingsPopup` and `ResultPopup` (no Rune prefix); existing component class names remain stable. Gate hit numbers use the downloaded Fredoka Bold at size 30 with a near-white cream face, dark brown outline and subtle lower shadow for strong contrast across every gate color, authored by `RuneGateNumberAuthoring` with the shared `Fredoka-GateNumbers.mat` preset. Apply the same styling to both gameplay gates and the lobby showcase; keep a single centered remaining-hit number.
- PlayPage has no hover trajectory or automatic mirror path guide; preserve the actual chain tethers. Storage uses five evenly spaced recessed pockets. `align-storage.cjs` preserves the original tray correction. The current `cabinet_clean.aseprite` and PNG combine the original unmarked chassis and corrected storage only: no empty gate channels, bypass arrows or success marks. Missing and destroyed gates expose the same clean cabinet. Retain older refined sources as history.
- PlayPage's long gates are continuous molded rectangles with exactly two round studs at 30% and 70% of their length and the remaining-hit number centered between them. `gate_studs_*` layered Aseprite sources preserve the original block colors and stud pixels; no end caps or center grooves. Campaign gates currently have at most two layers. Preview the one next layer using its full molded sprite, exposed 8 units above the north gate or 7 units right of the east gate; do not add a separate mini-block indicator. `ApplyRewardAndGates.TwoLayers` preserves block placements and total color hit counts, validates solvability, and retains the prior level data in `Source/BlockPunch/Surface/levels-before-two-layer.json`.
- Gate damage accumulates branching cracks through two prefab-authored `RuneGateDamageGraphic` instances with bounded mesh buffers. Grow cracks at each impact, clear them when a layer breaks, and show `Break!` using the existing authored caption pool and downloaded Fredoka Bold. Keep the remaining-hit number readable.
- Stored Surface blocks use the same 56-unit sprite size and center in all five 58-unit pockets, at full opacity. `RuneFlight.SurfaceStoredSize` is the shared presentation size: rebound landing interpolates to this size and automatic relaunch starts there, with no position or size jump at the pooled-flight/slot handoff. Verify this with `InspectSurfaceLayout.Verify`.
- Both lobby and gameplay settings controls use the same baked `settings_button.png` image and cached existing button callbacks. Popup text aligns to the visible molded face, accounting for transparent shadow padding; use Fredoka geometry alignment and keep these positions in prefab authoring. `comfy-surface.cjs --refined` exports the current assets through ComfyUI while the exact Aseprite composites remain the shipped masters.
- Reward and clean cabinet recipes live in `export-reward.cjs` / `author-reward.lua`, with layered Aseprite masters under `Source/BlockPunch/Surface`. `comfy-surface.cjs --reward` performs the source-material/alpha roundtrip; retain exact Aseprite composites as shipped PNGs, point-filtered and uncompressed in the existing BlockPunch atlas. Verify reward flow, four frame rebounds, accumulating cracks, background particles and pooled-coin cleanup with `RewardQA`; verify popup alignment at four aspect ratios with `SurfaceLayoutQA`.
- PlayPage now shares MainPage's navy/violet background using the existing prefab-authored `RuneLobbyScenery` with `punchStyle=true`, stretched over `FullScreenBackdrop`. Level text is cream with a muted lavender caption. `RuneSurfaceAuthoring.ConfigureBackdrop` preserves this on rebuild.
- The current board and storage material is `cabinet_lavender`, a light lavender-gray palette variant of `cabinet_clean`; preserve both ivory masters. `export-board-palette.cjs` / `author-board-palette.lua` retain the exact alpha, geometry and molded lighting. The palette uses frame `#CECADA`, inset `#777487` and cells `#9692A3`. Keep settings popup material unchanged. Verify the variant through `comfy-surface.cjs --board-palette` and register it in the existing atlas.
- The east gate and its next-layer preview are inset together by 8 Surface units so both colored faces fit inside the cabinet. `RuneFlight.SurfaceEastGateLeft` (412) and `SurfaceEastGateCenter` (426) are shared by sprite placement, numbers, cracks, flashes, impacts and chain anchors. Keep the 7-unit next-layer reveal, full sprite dimensions and round studs; bare-frame rebounds still use x=451.
- The result coin pile uses eight cropped original Aseprite layers authored under `RewardCoins`, controlled by cached `RuneRewardPile` references. Pieces briefly drop and settle on entry, then stay still; no periodic whole-pile scaling. Three small glints and subdued slow rays provide idle accents. Claim coins start at seven authored pile positions and accelerate into the wallet without stretching or repeated flips. Reuse the 12-instance baked coin pool and existing reward/navigation flow. Recipes and masters: `export-reward-motion.cjs`, `author-reward-motion.lua`, `reward-motion-manifest.json`; ComfyUI verification: `comfy-surface.cjs --reward-motion`.
- The shared wallet/flight/reward coin material is authored by `coin-material.cjs`: vivid yellow gold faces, orange-gold bevels, a milled sidewall and a chamfered star under one upper-left light, without bloom. Reference images guide the color mood only; preserve the existing coin design. Keep the six-layer Aseprite coin master and eight separately authored pile pieces; prior masters remain in `Surface/History/coins-before-satin` and `coins-before-yellow`. Reward rays use 0.26 opacity. `comfy-surface.cjs --button-coins` verifies alpha and black/white composites while the exact Aseprite exports ship. `ApplyButtonCoins.RefreshCoinMaterial` imports palette-only updates without reauthoring prefabs. `ButtonCoinsQA`, `RewardQA` and `SurfaceLayoutQA` cover interaction, cleanup and layout.
- `ApplyLobbyHero` updates only the MainPage decoration. `LobbyHeroQA` is the current lobby check: exactly four blocks, no showcase/unused pool, stable hierarchy, 30/60/120-fps motion, settings pause, reduced motion, four aspect ratios and unchanged navigation/progress. `LobbyHeroQA.Film` and `author-lobby-hero-preview.lua` export an actual Unity animation preview. Older showcase-focused QA utilities are historical.
- Result presentation is baked by `RuneRewardAuthoring.ConfigurePresentation` / `ApplyRewardArrival`: downloaded Fredoka Bold uses `Fredoka-ClearTitle.mat`, a cream-to-gold face, an authored gold depth copy and a brief entry pop. Wallet, bounded `RuneFxGraphic` reward effects and the existing 12-coin pool share one Canvas in that back-to-front order. Flights accelerate for 0.48 seconds with 0.05-second staggering, remain visible through a centered 0.085-second absorb, and trigger small rings/sparks plus an icon spring and cached `coin_pop` audio once per contact. Payment remains immediate and idempotent at Claim; navigation waits for every flight to return. `RewardArrivalQA` verifies actual rendered depth, stable contact, four ratios, 30/60/120 fps, reduced motion and cleanup. Its Film method and `author-reward-arrival-preview.lua` retain an actual Unity capture.
