# Project conventions

- The player-facing game title is BLOCK CRASH (블록 크래시). Existing RuneBreak code, asset paths and save keys remain stable. Entry flow: `Splash` scene → `Play` scene, with `MainPage` and `PlayPage` prefab instances registered in `PageManager`.
- Cache component dependencies in serialized prefab/scene fields. Do not use `GetComponent`, `GetComponentsInChildren`, `Find`, or `AddComponent` in runtime initialization. Editor authoring/build utilities may use these APIs to bake references.
- Inspect and reuse the existing `PoolManager`, `SpriteManager` / `SpriteAtlasSO`, and `PopupManager` regardless of their folder locations. Do not create parallel manager systems.
- Popups use the existing `PopupManager` with authored prefab references and a scene-authored `PopupParent`. Instantiating a complete popup prefab on open and destroying that instance after close is an approved exception; never build its UI hierarchy or add components at runtime. Cache its canvas, animation target, input blocker, controls and other dependencies in serialized fields.
- Default popup art uses the molded Block Crash material, with a centered title plaque overlapping its top border. The shared `PopupPanel` helper delegates its art to `RuneBlockUiAuthoring`; use the same authoring for settings and result overlays. Settings is titled `설정` and contains only background music, sound effects and a bottom `닫기` button, identically in the lobby and gameplay.
- Author UI, boards, slots and effects in prefabs. Avoid runtime hierarchy construction; use the existing `PoolManager` baked-pool path for flights and a bounded mesh buffer for particles.
- Reuse `SpriteAtlasSO` / `SpriteManager` and point-filtered, uncompressed sprite atlases. Keep the HTML prototype's exact pixel palette and drawing geometry.
- `Tools/RuneBreak/Source/rune-break-layers.html` is the fidelity reference. The export script runs its original drawing functions. Preserve Aseprite sources and compare exported pixels before changing art.
- Rules reserve damage and storage when tapped. Animation timing must not affect rules. Keep rules/solver independent of MonoBehaviour and validate against the HTML oracle.
- Ready boosters are three empty slots; their mechanics are undecided. Lobby tabs are data-driven and currently placeholders except Home.
- The HTML is a reference for art, rules and effects, not the shipped UI. Do not restore its named chapter heading, north/east text panels, debug statistics, undo/restart/hint buttons, or Z/R/H shortcuts. PlayPage uses the board, recast slots, top-right settings, and three bottom booster placeholders.
- Legacy pixel gate presentation overrides live in `Tools/RuneBreak/presentation.cjs`. Preserve these original sources; current MainPage and PlayPage use Block Punch art.
- MainPage and PlayPage share the user-requested Block Punch art from `Tools/RuneBreak/Source/BlockPunch/block-punch.html`, with exact PNG/Aseprite masters, two round studs on each continuous long gate, and one large remaining-hit number in its center (for example `2`, never `2/2`). Do not add a badge, `OK`, or a storage plaque. Keep future-layer previews. `RunePunchAuthoring` authors PlayPage; `RuneLobbyPunchAuthoring` authors MainPage. Both use the existing `SpriteAtlasSO` and the point-filtered, uncompressed BlockPunch atlas.
- MainPage uses the navy/violet glossy skin, rounded icons, gold Play button and automatic-only six-block showcase. The showcase has no touch target, surrounding frame, cell wells, subtitle or tap hint; blocks and the gate float over the background. Impacts emit colored beveled shards through the existing bounded `RuneFxGraphic` buffer. Keep existing navigation/button bindings and the prefab-local `RuneLobbyFlightPool` subclass of `PoolManager`. The showcase is silent and never changes campaign progress. Its background fills the entire canvas, while controls use the existing safe-area layout. Glossy panel recipes live in `RuneLobbySkinAuthoring`; coin/heart recipes are in `Tools/RuneBreak/export-lobby-icons.cjs`, with layered Aseprite masters in `Tools/RuneBreak/Source/BlockPunch/Lobby/Icons`. Currency icons share the existing BlockPunch atlas.
- Storage flights use the prototype's punch rebound: straight approach, local compression, inward kick, curved flight and landing. `RuneReboundMotion` is pure presentation, verified against the HTML samples; damage and storage remain reserved by the existing rules at tap time. Author all shadows, afterimages and ribbons in the existing 48-instance baked pool.
- The main Play button displays only `Lv. N`, following saved progress. Its molded face moves down when pressed. Buttons and popup frames derive their curved bevels and round studs from the original stored block art, baked to each control's dimensions to avoid distorted studs. Recipes: `Tools/RuneBreak/export-block-ui.cjs`; layered Aseprite sources: `Tools/RuneBreak/Source/BlockPunch/Lobby/Blocks`. Register their point-filtered, uncompressed sprites in the existing BlockPunch atlas.
