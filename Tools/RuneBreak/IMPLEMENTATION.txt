RUNE BREAK — Unity replacement

Open Assets/Scenes/Splash.unity and press Play. Splash loads Play; MainPage is the initial page.
MainPage and PlayPage are saved at Assets/Resources/Prefabs and are preplaced in Play.unity.
MainPage tabs use stable IDs: shop, leaderboard, home, team, modes. Modes uses a pixel gamepad icon. Only Home is implemented.
PlayPage has the puzzle, five recast slots, top-right settings, and three bottom ready-booster placeholders.
The HTML chapter names, north/east text panels, debug stats, undo/restart/hint controls and Z/R/H shortcuts are intentionally absent.

Runtime hierarchy is authored in prefabs. Serialized references are used by the game/page initialization.
PoolManager's baked pool supplies 48 flights with six cached trail images each.
Particle effects use a bounded 650-particle/48-wave mesh, without spawning GameObjects.
SpriteAtlasSO and SpriteManager register the point-filtered, uncompressed original-pixel atlas.
The rule model and solver are independent from MonoBehaviour. Damage/storage is reserved on input.
WAIT taps never consume a rune. Five stored runes are safe; only an additional stored rune loses.

Art source: Tools/RuneBreak/Source/rune-break-layers.html (unaltered copy of the supplied HTML).
export-original.cjs executes its original drawing code with presentation.cjs UI overrides to produce cabinet/runes/all gate-hole variants.
Gates show one colored block per remaining hit point; numeric badges, OK and TO POUCH are removed.
Source/RuneBreak.aseprite is the editable rune sheet. Aseprite PNG round-trip has zero differing channels.
export-audio.cjs renders the original oscillator/envelope/noise-filter recipes to WAV assets.
Sound randomness and the Web Audio compressor are not bit-identical between runtimes.
Comfy Desktop window access was rejected by automatic approval review; it was not used to regenerate art.

Regenerate assets: npm ci --prefix Tools/RuneBreak
node Tools/RuneBreak/export-original.cjs [prototype.html] [optional-level-catalog.json]
node Tools/RuneBreak/export-textless.cjs
node Tools/RuneBreak/export-audio.cjs
Then use Unity menu Rune Break / Rebuild pages and scenes. This explicitly replaces both page prefabs and scenes.
An optional level catalog uses the same {levels:[...]} schema as Assets/RuneBreak/Data/levels.json.
After changing layer counts/colors or adding levels, rerun export so matching gate art is baked.
The current board supports size 6, capacity 5, at most 28 runes including buried layers, and eight baked mirror views. Further board sizes need layout authoring.

Validation menu: Rune Break / Validate rules against HTML.
QA/rules-report.json records all 130 original solution transitions and 3,600 additional input scenarios.
All six levels solve; levels 5 and 6 cannot solve with capacity 4.
Live validation exercises rapid reservation, undo cancellation, stable hierarchy count, and a full level-6 solve.
RuntimePresentationReset verifies all six level transitions, immediate transform reset, page reentry, and 50 interrupted launches reusing all 48 pooled flights.
Undo and solver code remain as test/development helpers, not exposed gameplay controls.

Previous game-specific scripts, editor generators and resource prefabs were moved out of Unity into Archive/LegacyGame.
Its existing source/art, including the pre-existing modified Korean font asset, are preserved there.
Purchased asset packs and shared utilities were retained. HealerPrototype was not modified.

Three mechanic demos (October 18, 2026)
------------------------------------
Mechanic demos are levels 7, 8 and 9. The public Home demo selectors were removed in the lobby redesign.
Editor preview remains available through MechanicPreview.cs / Chain, Mirror and Stack.
They are separate from the six-level campaign; demo wins never update campaign progress.
Each demo can be solved without boosters; failure offers 다시 체험, and a win advances to the next demo.

Chain: RuneBlock.chainSide N/E plus zero-based chainLayer; the chain releases when that layer's final damage is reserved.
The impact then snaps the visible tether, throws metal links, flashes the connection and plays a metallic cue.
Rapidly tapped released runes reserve their move immediately; their flight can wait for the visible release.
Mirror: fixed RuneMirror (x,y,slash). '/' and '\' reflect the grid ray by 90 degrees.
Every blocker along the reflected path matters. Closed ray loops are rejected. The guide, flight and solver use the same cached route.
Stack: multiple runes may share (x,y) with increasing depth. Only the lowest remaining depth is selectable/blocking as the top surface.
All buried runes remain in rule inventory. Removing the top reveals the next immediately; its miniature shows both color and direction beforehand.
The new rune rises from its preview position with a short spring, diamond wave, lifting sparks and a reveal cue.

All objects are baked into PlayPage; 48 pooled flights and bounded particle/guide meshes are retained.
The three original booster placeholders remain undecided.
New art: Source/Mechanics.aseprite (four 48x48 tiles); exact palette pixels authored through Aseprite MCP.
author-mechanic-pixels.cjs records the pixel recipe; export-mechanic-art.cjs slices the Aseprite PNG and checks a zero-difference round trip.
Existing RuneBreak.aseprite, original HTML and 453 original PNG assets remain unchanged.
ComfyUI was not needed for the exact-pixel additions.

export-original.cjs appends demo-levels.json by default and uses mechanics-oracle.cjs for extended levels.
The six original solution traces still come directly from the untouched HTML engine.
Run node Tools/RuneBreak/test-mechanics.cjs before executing MechanicQA.cs / Rules in the Unity editor.
Rules compares 3,440 independent object-based oracle cases, 40 paths and the nine solutions against C#.
MechanicQA.cs / Runtime checks rapid unlocks, 6 live solves (normal + reduced), stack raycasts, settings pause, resets, baked hierarchy stability and demo navigation/progress isolation.
MechanicPreview.cs / Film renders actual Unity frames at 20 fps; QA/Mechanics-demo.gif is a silent 15-second preview. In-game audio has three new cues.

Galmuri typography (October 18, 2026)
------------------------------------
All shipped text uses TextMeshPro with Galmuri11 Regular/Bold copied from Project_SH/Assets/Font/Galmuri.
Font sources and OFL license are in Assets/RuneBreak/Fonts/Galmuri; the source project is unchanged.
RunePixelText and its glyph table/export were removed. Particle and icon geometry use RuneUiMesh, which contains no text rendering.
RuneFontAuthoring bakes both font atlases at 12px RASTER_HINTED with point filtering and all 11,172 modern Hangul syllables.
UI sizes are integer multiples of 12. All shipped UI text uses the real Bold typeface.
Effect text uses 24 prefab-authored caption pairs plus a chain label; runtime only changes text, position, color and visibility.
export-textless.cjs makes 11 cabinet/wait variants without baked text, and verifies zero differences outside inscription regions.
Original PNGs, HTML and Aseprite sources remain intact. Compass/recast/slot text is now authored as TMP components.
FontQA.cs validates font coverage, prefab references, caption delay/lifetime/reuse, WAIT state, and settings layout.

Managed settings popup (October 20, 2026)
----------------------------------------
MainPage and PlayPage open the shared Resources/Prefabs/Popups/RuneSettingsPopup.prefab through the existing PopupManager.
The Play scene authors PopupManager/PopupParent, the render camera and the prefab registration; PageManager owns Escape routing.
The manager caches the prefab asset and creates a complete instance under PopupParent on open. Close destroys the instance after its animation.
Canvas, CanvasGroup, controls, animation panel and full-screen transition input blocker are all prefab-authored and serialized.
BasePopupHandler no longer discovers components or constructs an input blocker. PopupManager uses its already-existing singleton and assigned camera.
Only the panel scales during transitions; the curtain and transition blocker continue to cover the full screen.
Opening/closing/queued requests block board input and pause presentation. Page exit cancels pending requests and removes live instances.
Default popup frame: sliced pixel panel with a centered gold title plaque overlapping its top edge; author future popups with the shared PopupPanel helper in RunePopupAuthoring.
Settings has the title 설정, separate 배경음/효과음 toggles and a bottom 닫기 button, identically in lobby and gameplay. All close paths save preferences.
Music uses the existing SoundManager Sound_BgmOn preference and applies to an already-present manager; Rune Break currently has no assigned background music track. SFX keeps the existing RuneBreak.Audio path.
Reduced motion, path preview and volume retain their stored preferences but are no longer shown in settings. The result overlay is still owned by PlayPage.
Rebuild the visual prefab with Rune Break / Rebuild settings popup only; use Rebuild settings popup and wire manager when authoring scene connections.
QA: PopupQA.cs; popup-runtime-report.json covers title plaque, audio controls, repeated opens, prefab hierarchy, destruction, settings persistence, pause, back, page exit and queue.
