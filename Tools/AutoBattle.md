# 자동 원정 / 편성 구현 기록

## 구조와 동작

- 실제 Play 씬의 `PlayPage` / `ExpeditionModel`을 확장했다. 별도 구형 `BattleController` 경로로 게임을 옮기지 않았다.
- 유효한 편성은 자동 이동 2.2초 → 전투 → 승리 연출 1.1초 → 다음 이동을 반복한다. 패배는 `PlayPage.retryDelay`(기본 3초) 후 같은 웨이브를 새 전투로 재시작한다. 프리팹 Inspector에서 조정 가능하다.
- 기본 공격 간격은 장착 무기의 실제 interval을 사용한다. 적은 전열부터 살아 있는 영웅을 찾는다. 매 전투 HP, 공격 타이머, 스킬 쿨타임, 빙결을 초기화한다.
- `ExpeditionBattle.cs`는 전투 시작 시 영웅별 능력치, 장비 ID, 스킬 정의와 슬롯 순서를 복사한다. 현재 전투와 저장 설정을 분리하여 편성/장비 변경이 현재 공격·체력·표시에 영향을 주지 않는다.
- 승패는 Fighting 가드로 한 번만 처리한다. 승리 보상과 다음 진행도를 같은 저장 데이터에 반영하고 즉시 저장한다. 패배에는 보상이 없다. 기존 보스 재료 보상과 cleared 기반 해금을 유지한다.
- 일반 메뉴를 열어도 전투는 진행한다. 기존 모달 팝업/앱 백그라운드 일시정지 정책은 유지한다. 채굴 입력은 플레이 탭에서만 받는다.

## 편성 / UI / 저장

- `HeroRoster`: 안정적인 ID `rowen`, `rin`, `mira`. 기존 영웅 인덱스는 장비/표시 조회용이며 편성 위치로 사용하지 않는다.
- 3개 슬롯 선택 후 영웅을 선택한다. 교환, 빈 슬롯 이동, 미출전 영웅 교체, 마지막 1명을 보호하는 해제를 지원한다. 직업 제한은 없다.
- 영웅 메뉴에 전열/중열/후열, 빈 슬롯, 출전 위치, 추천 위치, 별도 장비 관리 버튼과 적용 대기 안내를 추가했다. 추천은 기존 역할에 따라 전사 전열, 도적 중열, 마법사 후열이다.
- 전투 배우와 체력바는 영웅 ID에 연결하고, 위치만 슬롯에 맞춘다. 자동전투 토글과 이벤트/빌더 참조를 제거했다.
- 기존 PlayerPrefs 키 `ProjectSS.Play.v3`를 유지하고 내부 version은 4로 올렸다. 재료, 인벤토리, 영웅 장비, 진행도는 유지한다.
- v3는 기존에 보유하던 3명을 기본 편성한다. null/빈 배열, 잘못된 ID, 중복, 미보유, 전원 빈 편성을 보정한다. 복구할 보유 영웅이 하나도 없으면 기본 영웅 로웬을 사용한다.
- 기존 autoBattle=false는 무시한다. 재접속은 저장된 현재 웨이브의 새 전투로 시작한다. 중간 HP나 보상 예약을 복원하지 않는다.

## 스킬 조사 / 필요한 기획

- 현재 완전한 스킬 에셋은 `Assets/Prototype/Skills/frost_nova.asset`: 빙결, 적 범위, 쿨타임 10초, 확률 100%, 지속 2초, 반경 3. 이를 자동 실행에 연결했다.
- 기존 전투는 한 번에 적 1명이다. 범위 스킬은 해당 적 중심으로 처리한다. 다수 적을 추가하는 기획은 만들지 않았다.
- 초기 쿨타임이 지난 뒤 발동한다. 유효한 대상이 있어야 하며, 사망/전투 종료 후에는 발동하지 않는다. 확률 판정 실패도 한 번의 쿨타임 기회로 처리한다.
- 전투 효과는 동기 상태 갱신으로 처리하여 이전 전투의 예약 피해가 없다. 선택적 visualPrefab과 스킬 동작을 활용하며 전투 종료/다음 전투에서 이전 VFX를 정리한다.
- 실제 카탈로그 장비에는 현재 이 스킬이 지정되어 있지 않다. 임의로 기존 장비를 전설 등급으로 바꾸거나 스킬을 부여하지 않았다. 검증은 복제 카탈로그의 전설 장비에 빙결을 지정하여 수행했다. 실제 획득 장비에 부여할 대상과 등급은 기획 결정이 필요하다.
- Damage/Heal/Shield의 power 단위·적용식, Burn의 피해 간격과 수치, OnCriticalHit의 치명타 판정 규칙은 정의가 불완전하여 실행하지 않는다. 이 항목은 미구현이다. 스킬 없는 장비는 기본 공격으로 동작한다.
